# CR0001 — Implementation spec for a Sonar custom C# rule

> **Audience:** an automated rule-authoring agent (Sonar AI agent, or a developer writing a Roslyn analyzer
> for the `creatio-csharp` rule repository). This file carries the detection logic; `CR0001.html` carries
> the user-facing description and `CR0001.json` the rule metadata.

- **Repository:** `creatio-csharp`
- **Rule key:** `CR0001`
- **Language:** C# (`cs`)
- **Type:** Code smell · **Severity:** Major · **Clean Code attribute:** Conventional
- **Impacts:** Maintainability `HIGH`, Reliability `MEDIUM`

---

## 1. Intent in one sentence

In Creatio server-side code, a value that expresses **business policy** must be read at runtime from a
Creatio system setting that the package actually ships — not compiled into the assembly as a literal.

## 2. Scope

Analyse:

```
packages/*/Schemas/**/*.cs
packages/*/Files/src/cs/**/*.cs
```

Skip entirely:

```
packages/*/Autogenerated/**      # generated by the platform; regenerated on every package load
tests/**                         # fixed expected values are the point of a test
**/obj/**, **/bin/**
```

A file is in scope only if it declares a type in the `Terrasoft.Configuration` namespace, or derives from
one of the Creatio extension base types listed in §3.1. This keeps the rule off plain helper/DTO code.

## 3. Detection

### 3.1 Business-logic contexts

Raise only inside a method that belongs to a Creatio extension point. Recognise a type as such when it:

| Signal | Example |
|---|---|
| carries `[EntityEventListener]` | `[EntityEventListener(SchemaName = "UsrYacht")]` |
| derives from `BaseEntityEventListener` | `class YachtEntityEventListener : BaseEntityEventListener` |
| derives from `BaseService` (configuration web service) | `class YachtService : BaseService` |
| derives from `ProcessUserTask` / `ProcessScriptTask` | process script task |
| derives from `BaseMessageHandler`, `IEntityEventListener`, `BaseRule` | other extension points |

### 3.2 Primary pattern — threshold literal in a business comparison

Report a `LiteralExpressionSyntax` (or a `const` field reference whose initialiser is a literal, see §3.4)
when **all** hold:

1. it is an operand of a `BinaryExpressionSyntax` with one of `>`, `<`, `>=`, `<=`, `==`, `!=`;
2. its type is numeric (`int`, `long`, `decimal`, `double`, `float`) **or** it is a `Guid` construction from a
   literal string (`new Guid("…")`, `Guid.Parse("…")`);
3. the **other** operand resolves to entity or business data, i.e. one of:
   - `GetTypedColumnValue<T>("…")`,
   - an `Entity` indexer / column accessor,
   - a `Select(...).ExecuteScalar<T>()` result,
   - a local whose initialiser is any of the above (follow one level of assignment);
4. the literal is not in the allow-list of §3.5.

**Message:**
`Read this threshold from a Creatio system setting instead of hard-coding {LITERAL}. Bind it to a 'private const string' setting code, read it via SysSettings.GetValue<T>(UserConnection, code, fallback), and ship the setting in Data/SysSettings_<Code>/.`

Secondary location: point at the entity-data operand so the reader sees what is being compared.

### 3.3 Secondary pattern — threshold restated in a message

Report a numeric-looking string literal (regex `\d[\d\s.,]*\d`) passed as an argument to `string.Format`,
`string.Concat`, or an interpolated string, when the enclosing method already produced a CR0001 primary
issue, **or** when the format template is a `LocalizableString`.

**Message:**
`Do not restate the threshold in the message. Pass the system-setting value as the format argument and use a '{0}' placeholder in the localizable string.`

Also report when a `LocalizableString` resource value itself contains a digit run of 3+ characters and the
resource is used as a `string.Format` template — the number belongs in the argument, not the translation.

### 3.4 The `const` does not launder the literal

`private const decimal MaxPrice = 100000m;` followed by `if (price > MaxPrice)` **is still an issue.** Resolve
`const` field references to their initialiser before applying §3.2. This is the single most common false
"fix" and the rule must not accept it.

Distinguish by type: a `const string` whose value is a setting **code** (matched in §3.6) is compliant and
must never be reported. A `const` of numeric or `Guid` type used in a business comparison is reported.

### 3.5 Allow-list (never report)

- Literals `-1`, `0`, `1`, `0m`, `Guid.Empty`, `null`, `string.Empty`.
- Comparisons whose data operand is `.Count`, `.Length`, `.Rows.Count`, `.Count()`, `.Any()`.
- HTTP status codes, array indices, `TimeSpan` unit conversions (`* 1000`, `* 60`, `* 24`), buffer sizes.
- Literals inside `switch` labels over an enum, and inside attribute arguments.
- Any expression inside a method annotated `[Obsolete]` or a region marked `// CR0001: technical constant`.

### 3.6 Compliant shape — what the fixed code must look like

A comparison is compliant when its threshold operand flows from:

```csharp
Terrasoft.Core.Configuration.SysSettings.GetValue<T>(<userConnection>, <settingCode>, <fallback>)
```

where `<settingCode>` is an **identifier referencing a `const string` field** declared on the containing type
(binding #2). An inline string literal in that argument position is itself an issue:

**Message:**
`Bind this system setting code to a 'private const string' field rather than repeating the literal "{CODE}".`

`SysSettings.GetValue<T>(UserConnection, code)` without an explicit fallback is acceptable, but see §3.7.

### 3.7 Unconfigured-setting guard

`GetValue` returns the fallback when the setting is missing or blank. A `0` fallback used directly as a
threshold silently inverts the rule's meaning — a `0` maximum rejects every record. Report when the value
returned by `GetValue` reaches a business comparison **without** an intervening guard on the same value
(`if (x <= 0) return;`, `if (x == Guid.Empty) …`, `x > 0 &&` in the condition, or a null/`HasValue` check).

**Message:**
`Handle the unconfigured case: SysSettings.GetValue returns the fallback when '{CODE}' is absent, and a fallback of {FALLBACK} would be applied as a real threshold.`

### 3.8 Cross-file binding — the setting must ship with the package (binding #3)

This check needs repository context beyond the single compilation unit. Run it as a project-level /
sensor-level check rather than inside the syntax walker.

For every `const string` setting code identified in §3.6, resolve the owning package from the file path
(`packages/<PKG>/…`) and assert that **both** directories exist:

```
packages/<PKG>/Data/SysSettings_<Code>/data.json
packages/<PKG>/Data/SysSettingsValue_<Code>/data.json
```

Additionally, parse `SysSettings_<Code>/data.json` and confirm a row whose `Value` equals `<Code>` for the
`Code` column (`SchemaColumnUId` `13aad544-ec30-4e76-a373-f0cff3202e24` in a standard `SysSettings` descriptor)
— a folder named after the code but carrying a different `Code` value is a copy-paste bug and must be reported.

If the package depends on another workspace package, also search that package's `Data` folder before
reporting (read `packages/<PKG>/descriptor.json` → `Descriptor.DependsOn[].Name`).

**Message:**
`System setting '{CODE}' is read here but no package ships it. Add Data/SysSettings_{CODE}/ and Data/SysSettingsValue_{CODE}/ to package '{PKG}', otherwise this code silently falls back to {FALLBACK}.`

If cross-file analysis is unavailable in the target rule engine, emit this as a **separate rule CR0002** at
severity Major and keep CR0001 to §3.2–§3.7.

### 3.9 Type agreement (advisory, same rule)

When the setting's `ValueTypeName` in `data.json` is known, check it against the `GetValue<T>` type argument:
`Float`→`decimal`/`double`, `Integer`→`int`, `Boolean`→`bool`, `Text`/`ShortText`→`string`, `Lookup`/`Guid`→`Guid`,
`Date`/`DateTime`→`DateTime`. Report a mismatch — Creatio will return the fallback rather than throw.

## 4. Test corpus

The analyser must produce exactly the expected verdict on each case.

| # | Snippet (inside an `[EntityEventListener]` class) | Expected |
|---|---|---|
| 1 | `if (price > 100000) { … }` | **Issue** §3.2 |
| 2 | `private const decimal Max = 100000m; … if (price > Max)` | **Issue** §3.4 |
| 3 | `var max = SysSettings.GetValue<decimal>(uc, "UsrYachtMaxPrice", 0m); if (price > max)` | **Issue** §3.6 (inline code) + §3.7 (no guard) |
| 4 | `const string C = "UsrYachtMaxPrice"; var max = SysSettings.GetValue<decimal>(uc, C, 0m); if (price > max)` | **Issue** §3.7 only (no guard) |
| 5 | case 4 + `if (max <= 0) return;` before the comparison, and `Data/SysSettings_UsrYachtMaxPrice/` present | **No issue** |
| 6 | case 5 but the `Data/SysSettings_*` folder is absent | **Issue** §3.8 |
| 7 | `if (statusId == new Guid("a29a3ba5-…"))` | **Issue** §3.2 (Guid literal) |
| 8 | `if (rows.Count > 0)` | **No issue** §3.5 |
| 9 | `if (retries > 3)` where `retries` is a local loop counter, not entity data | **No issue** (§3.2 condition 3 unmet) |
| 10 | `string.Format(template, "100 000 EUR")` in a method that also triggers case 1 | **Issue** §3.3 |
| 11 | resource `Value="No yacht should cost over 100000"` used as a `string.Format` template | **Issue** §3.3 |
| 12 | resource `Value="No yacht should cost over {0:N0}"` + `string.Format(template, maxPrice)` | **No issue** |
| 13 | `GetValue<int>(uc, C, 0)` where the setting's `ValueTypeName` is `Float` | **Issue** §3.9 |
| 14 | any of the above inside `packages/X/Autogenerated/Src/*.cs` | **No issue** (out of scope) |

## 5. Reference fix

The change that motivated this rule, as a before/after pair:

- **Before:** [`UsrYachtEvents.cs`](../../../packages/UsrYacht/Schemas/UsrYachtEvents/UsrYachtEvents.cs) compared
  `UsrPrice` against the literal `100000` and restated `"100 000 EUR"` in the message, against a resource string
  that itself read `"No yacht should cost over 100000"` and carried no `{0}` placeholder — so the format
  argument was silently discarded.
- **After:** the threshold is read from the `UsrYachtMaxPrice` Float system setting via a `const string` code,
  the unconfigured case returns early, the setting ships in
  `packages/UsrYacht/Data/SysSettings_UsrYachtMaxPrice/` with a default of `100000.00`, and the resource reads
  `"No yacht should cost over {0:N0}"`.

Use case 1 as the canonical noncompliant fixture and the post-fix file as the canonical compliant fixture.

## 6. Packaging notes

- For a **SonarQube custom plugin**: implement as a `SonarAnalyzer`-style Roslyn `DiagnosticAnalyzer`
  (`DiagnosticId = "CR0001"`), register on `SyntaxKind.GreaterThanExpression` and siblings, and expose the
  rule through a `RulesDefinition` loading `CR0001.json` + `CR0001.html` from
  `org/sonar/l10n/cs/rules/creatio-csharp/`.
- For **SonarQube external-issue import**: emit the findings in the
  [generic issue import format](https://docs.sonarsource.com/sonarqube-server/latest/analyzing-source-code/importing-external-issues/generic-issue-import-format/)
  and point `sonar.externalIssuesReportPaths` at the JSON.
- Add `CR0001` to the `Creatio way` quality profile and mark it as blocking in the quality gate on new code.
